## Plain, tidied text

- **Text a person types that is stored and printed is tidied and plain** (`core/http/text.ts`), in every catalog and in a doctor's profile: a name, a unit, a brand, a description. `PLAIN_TEXT` is the pattern for its schema: no control characters and nothing that prints as nothing (Unicode's default ignorable code points, named as `\p{Default_Ignorable_Code_Point}`: the zero-width space, the soft hyphen, the direction marks and overrides, the word joiner, the tag characters and the like, #322) and the braille blank, with the joiners Indic scripts need allowed, and the two variation selectors of emoji (U+FE0E, U+FE0F) right after an emoji only. Left allowed on purpose: the Egyptian hieroglyph format controls and the prepended concatenation marks, which are not default ignorable and are no Indian hospital's text; a whitespace look-alike (a no-break space) is made a plain space by `tidy`. A pattern compiled without the unicode flag lets all of it through, so it is never compiled so. A pattern must stay valid without the unicode flag, because that is how a schema's patterns are checked when the app starts: `\p{...}` is, a range written `\u{...}` is not. `tidyWithin` and `tidyOptional` give what is stored: one normal form (NFC), runs of spaces made one, none at the ends, and refused (400) when longer than the column once tidied, because a few letters become two characters in the normal form. Text of several lines (a description) uses `PLAIN_LINES` and `tidyLinesOptional`: the same for each line, with at most one empty line between two paragraphs. So two names that look the same are the same row, and a label reads as it was typed. A new field of this kind uses them; a pattern that only refuses a NUL is not enough. The web app's forms check the same patterns (`shared/utils/text.ts` there, a copy that `text.test.ts` compares with this one). **A search term is tidied, never refused** (`searchTerm`): a control character is a space and what prints as nothing is gone, so a pasted tab or zero-width space finds what the term without it finds. The search schemas carry no pattern. **Rows written before #306 are left as they are:** no migration rewrites a name, because tidying two old names could make them one and there is no rule for which to keep. A text is tidied the next time it is sent, and one sent as the row already has it, apart from its spacing, changes nothing.
