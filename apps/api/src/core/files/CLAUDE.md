# core/files

`FileStore` (`put`, `get`, `delete`) keeps report exports, imaging files and patient documents. Two adapters, chosen by `FILE_STORE`:

- `local` (default): a folder (`FILE_STORE_DIR`). Development and tests only; **production refuses to start with it** (`core/config`), since a container loses its disk on redeploy and several containers would each have their own.
- `s3` (#695): `S3FileStore`, any S3-compatible service. Needs `S3_BUCKET` and `S3_REGION`; `S3_ENDPOINT` for a service other than AWS (path-style addressing is then used); `S3_ACCESS_KEY_ID` and `S3_SECRET_ACCESS_KEY` both or neither (neither means the task or instance role); `S3_SERVER_SIDE_ENCRYPTION` (`AES256` or `aws:kms`) when the bucket does not encrypt by default.

Malware scanning (#560): `MALWARE_SCANNER=test|clamav`. `clamav` needs `CLAMAV_HOST` (`CLAMAV_PORT` 3310, `CLAMAV_TIMEOUT_MS`); the daemon's `StreamMaxLength` must be at least 100 MB (imaging). Production refuses to start unless it is `clamav` with a host (#890).

Decisions:

- Objects are never public. By default the browser never reaches the bucket: the API reads and writes objects and serves downloads and accepts uploads through its own HMAC-signed, expiring links (`signing.ts`). With `S3_DIRECT_LINKS=true` (#765, off by default because the bucket then needs a CORS rule for the app's origin, `GET` and `PUT`) the S3 adapter's `presign` (download, with the file name and type forced) and `presignUpload` (the content type and exact size are signed, so the bucket refuses any other) give the browser the bucket's own addresses. `directLinks(app)` (`direct.ts`) is the one switch callers use. The checks stay in the API: a download address is made only after the hospital, permission and scan status are checked; an upload is announced (size and type limits) and then confirmed by a `complete` call that reads the object back (`size`, first bytes) and only then starts the scan, deleting an object that fails. Radiology images do this (`POST /radiology/images/{id}/complete`, `direct: true` in the upload answer); reports use `presign` for downloads. Documents (#194) still use the API's links.
- Keys start with the hospital's id; a signed link names a record id, and the record is read under the caller's hospital (or the worker role by id), so a link for one hospital's file cannot serve another's.
- Bucket setup (infrastructure, #145): block all public access, default encryption (SSE-S3 or KMS), versioning off, a lifecycle rule for aborted uploads, and a policy that lets only the API's role read and write.
- Tests: the report and radiology upload tests take their store from `test/file-store.ts`: a fresh bucket when `S3_TEST_ENDPOINT` is set, a temporary folder otherwise (#764). `s3-store.test.ts` runs when `S3_TEST_ENDPOINT` is set (CI starts RustFS; locally `docker compose --profile full up -d minio`, the service name kept, then `S3_TEST_ENDPOINT=http://localhost:9000`). MinIO no longer publishes images, so the compose service runs RustFS.
