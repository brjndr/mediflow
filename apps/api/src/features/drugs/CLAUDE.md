# Drugs and consumables API

What was decided for this feature's API. Moved out of `apps/api/CLAUDE.md` (#370); Claude Code loads it when a file of this folder is read. The web side's notes are in `apps/web/src/features/drugs/CLAUDE.md`.

- **`features/drugs`** is what each medicine and consumable the hospital keeps is: no price and no stock, which go with the batch in the pharmacy. Reference data with no patient data. Behind the `drugs` module flag, with `drug:read` for those who prescribe, request, dispense and store, and `drug:manage` for the admin.
- **The same item is not added twice:** generic name, brand, form and strength, whatever the capitals, archived or not (409 `drug_exists`), by a unique constraint on stored lower-case columns in which a missing brand or strength is the empty text. Items that are only similar are the caller's to judge: `POST /drugs/duplicate-check` gives up to ten with the same generic name in the same form.
- **Schedule X and narcotic items are controlled, whatever is sent,** in the route and by a check constraint. The schedules are India's and fixed in the contract for now (Open Decisions in the root `CLAUDE.md`).
- **A change of `schedule` or `controlled` is audited as `reclassify`,** any other change as `update`, so taking an item out of a controlled schedule leaves its own trace. The event names the changed fields, never their values.
- **Optional text is absent, never empty:** an empty brand, strength or unit in a change removes it, and a null reorder level removes the level. The level is one schema with both types, not a union (see Rules).
- **Names are tidied and plain** (`core/http/text.ts`: `PLAIN_TEXT` for the schema, `tidy` and `tidyOptional` for what is stored): normalised (NFC), runs of spaces made one, and nothing that prints as nothing (Rules), so that two items that look the same are the same and a label reads as it was typed. The joiners Indic scripts need are allowed, and an item is compared with the others without them (#322): the duplicate refusal (`drugs_same`, a unique index beside `drugs_exists`), the duplicate check and `beside_controlled` compare the stored `generic_key`, `brand_key` and `strength_key` of migration 0031. Two requests that add a controlled and an uncontrolled item of the same name at the same moment do not see each other, and no lock is taken for it: why is in the module notes.
- **An item that is not controlled, beside a controlled one, leaves a second audit entry** (`beside_controlled` on `drug`): when it is added, or renamed or moved to another form, and the hospital has a controlled item of the same generic name in the same form, archived or not (#306). Archiving a controlled item and adding it again under another spelling of its strength breaks no rule in any one request, and would otherwise take it out of its schedule with no `reclassify`. It is a trace, not a refusal: a generic name can rightly have a controlled and an uncontrolled strength. It goes by the `controlled` flag, not by the schedule. There is no `drug:reclassify` permission: `drug:manage` is the admin's alone by default, and a second permission would have to cover adding beside a controlled item too to mean anything. It can be split out when a hospital asks, with role management (M14).
- **The search is `POST /drugs/search`,** by generic name then brand, every word in either, with filters for type, form, schedule and controlled. Like the services search it matches the stored `search_text` of the hospital's rows and is not audited.
- **A dispense, a stock entry and a prescription line will store what the item was** (name, brand, form, strength, schedule, controlled) when the line was written, so renaming or reclassifying here never changes history. That is theirs to do (M7, M10); nothing here keeps versions of an item.
- **`POST /drugs` accepts an Idempotency-Key** and stores the whole answer for a replay.
- **Exports** from `index.ts`: `prescribableDrug`, a medicine that is not archived with its name as a prescription line reads it (generic name, strength, brand), which the clinical module prescribes (#86).
