# Insurance API

What was decided for this feature's API (BE-28, #187). Claude Code loads it when a file of this folder is read. The web side is `apps/web/src/features/insurance/CLAUDE.md`.

**Two slices.** First: payers, plans and rate agreements, a patient's policies, and pre-authorizations (migration 0098, switch `insurance`). Second: the coverage split and claims (migration 0099). Still in `packages/contract/planned.openapi.json` with the web mock behind them: corporate credit with receipts (#185). Delete it from the planned file when it lands.

- **Permissions:** `payer:read|manage`, `policy:read|manage`, `preauth:read|manage`. The admin holds all; the receptionist reads payers and manages policies and pre-authorizations (the "create/view" cell of the matrix). `claim:read|manage|writeoff`: the admin holds all, the receptionist reads and manages claims, only a holder of `claim:writeoff` gives up money. The receivable permissions come with the credit slice.
- **Payers** (`insurer`, `tpa`, `corporate`): the code and kind never change (a trigger), the code is unique per hospital whatever its capitals (409 `duplicate_code`). `PATCH` sends the changed fields and the `version` (409 `version_conflict`); a contact field sent as `null` is cleared. The list is a `GET` with `q` (name or code), because nothing about a patient is searched here.
- **Plans** replace their terms as a whole: when any term or the services are sent, a limit or age left out is removed; `archived` alone changes nothing else. Services are kept by id in `payer_plan_services` (422 `unknown_service`, `duplicate_service`). An archived organisation takes no plan (409 `payer_archived`).
- **Rate agreements** are never edited: a trigger lets only `effective_to` change, and an exclusion constraint on closed date ranges (no end is open-ended) keeps one organisation's agreements apart (409 `agreement_overlap`, also when ending later runs into the next). A start in the past is judged on the hospital's clock (422 `starts_in_past`). The rates table is insert-only for the application role.
- **Policies** are ended, never edited or deleted (trigger). `status` is worked out per request: `ended`, else `expired` once `validTo` is before today at the hospital, else `active`. The same card on the same plan is on a record once while in force (partial unique index, 409 `duplicate_policy`). A patient the caller may not read, and one that does not exist, are the same 404 `patient_not_found`. Reads are audited per policy.
- **Pre-authorizations** go `submitted -> approved | rejected | cancelled`, once (trigger and handler, 409 `not_submitted`); `approvedMinor` exists exactly when approved (a CHECK; 422 without it). Documents are names only, as in the web app. `billedMinor` is the sum of the visit's charges that are not void, read from the charge ledger when the request is listed, so it is always current; a request with no visit has 0.
- **Idempotency:** creates require an `Idempotency-Key`; ending, deciding and withdrawing accept one.
- **Domain events:** `claim.submitted` (on submit) and `claim.settled` (on settle), with ids and the amount received, never a name or a document.
- **Coverage split** (`split.ts`, `computeSplit`): worked out per request from the charge ledger (void charges left out, in posting order), the patient's newest active policy (404 `no_active_policy`), the plan's terms and the agreement in force today at the hospital. Order of the rules per charge, as in the web mock: the payer's agreed rate for the service times the quantity, else the list total less the agreement's discount (half up); covered or not (`all_except` or `only_listed`); the per-service limit, counted across the visit's charges of that service by what the payer has paid; the co-pay share (half up); the sum insured over the visit. Whole minor units, so payer + patient = rated on every line. `POST` keeps the figures in `coverage_splits` (one row per visit, replaced on a new save); `stale` is true when the ledger total has moved since. Reads need `policy:read`, `charge:read` and a patient the caller may read; saving `policy:manage`.
- **Claims** (`claims.ts`): `claims` (numbered `CLM-000001` from a per-hospital gapless counter, `claim_counters`), `claim_events` (append-only history, newest first in the detail). A claim is made from the split as it is now (its payer share becomes `claimedMinor`, never changed), not from the saved copy; 422 `nothing_to_claim` when the payer owes nothing. One claim in play per visit: a partial unique index over every status but `cancelled` and `written_off` (409 `claim_exists`). The state machine is `CLAIM_TRANSITIONS` in `claims.ts` and the same table as the web mock; anything else is 409 `invalid_transition`, a stale `version` 409 `version_conflict`. `outstandingMinor` is claimed less received and written off for a claim in play (zero for draft, cancelled, written off) and a write-off takes exactly that, only while it is above zero. Approve is at most the claimed amount, settle at most the approved amount (422). `GET /claims/aging` buckets the outstanding money of sent claims by whole days since `submitted_at` (0-30, 31-60, 61-90, over 90) per payer, on the database clock. Claims are not scoped to a patient the caller may read on the list and detail (the billing desk reads them, as with invoices); creating needs the patient in scope. The attachment packet is names only for now.
