# Triage API

What was decided for this feature's API (#79). Claude Code loads it when a file of this folder is read. The web side's notes, which hold the rules the screens and this API share, are in `apps/web/src/features/triage/CLAUDE.md`.

- **`features/triage`** is a patient's vital signs and chief complaint, the normal ranges they are marked against, and the patient's allergies. Behind the `triage` module flag, with `vitals:read` and `allergy:read` (admin, doctor, nurse) and `vitals:record` and `allergy:update` (admin, nurse), the "Triage and vitals" row of `docs/PRODUCT.md`. It implements what `planned.openapi.json` held for the web app (#77), with the same names and codes.
- **Readings are append-only in the database.** The app role may INSERT and SELECT `vitals`, and UPDATE only `encounter_id`; a trigger refuses any other change, and setting it twice. A correction is a new row with `corrects_id` and a reason (`vitals_correction`), and the partial unique index `vitals_corrected_once` lets a reading be corrected once, also between two corrections sent at the same moment (read as 422 `already_corrected`). A correction takes the token and the encounter of the reading it corrects, on the server.
- **The limits of a body are checks of the table** as well as the route's schema, and blood pressure goes together with the diastolic below the systolic (`vitals_blood_pressure`). One decimal is checked in the handler (`toFixed(1)`), since JSON Schema's `multipleOf` is not exact for decimals. Temperature, weight and height are `numeric(…, 1)` and read back as numbers (`::float8`).
- **A token is taken only when it is this patient's and today's at the hospital,** in any status (a re-check after the consultation), else 422 `token_not_for_patient`.
- **Ranges:** `vital_ranges` holds a hospital's own adult ranges, read-only for the app until #378. A hospital with no row uses the built-in ones (`DEFAULT_RANGES`, the same as the mock's hospital); one with some rows uses only those. A patient under 18 on today's date at the hospital gets `null` (#379). Reading the ranges is audited (`vital_ranges`, with the patient id), as it tells whether the patient is under 18.
- **Allergies** are one row per patient (`allergy_lists`), replaced whole: from version 0 an insert that does nothing when a row exists, from any other an update `where version = $v`, so of two saves at once the second is 409 `conflict` and changes nothing. No row is `unknown`. Every version is also written to `allergy_list_versions` (migration 0037) in the same transaction, which the app may only insert into and read, so what was removed, when and by whom stays known. Items are a JSON list checked by the route and the table (`none` with none, `listed` with 1 to 50), their text tidied. No idempotency key: the version does that job.
- **Scope:** every route finds the patient within the scope of its own permission (`vitals:read`, `vitals:record`, `allergy:read`, `allergy:update`) through `patientInScope` from `features/patients`, which decides what `own` and `department` mean. A patient outside it, of another hospital, or of none, is 404 `not_found` on every route, as is a reading of another patient.
- **The token check is the queue's** (`tokenOfPatientToday` from `features/queue`): triage does not read `queue_tokens` itself.
- **Audit:** `vitals` (`create` when recorded, `read` for the record, every row of a page, and a repeated recording), `allergy_list` (`read`, `update`) and `vital_ranges` (`read`), with the patient id for the last two. **Events:** `vitals.recorded` (the reading, patient, token and corrected reading when there are) and `allergy.updated` (patient and new version, never the allergies), through the outbox.
- **`encounter.opened`:** the module's subscriber sets `encounter_id` on the readings of the token in the event's payload (`queueTokenId`; the encounter is the event's entity id) that have none, so a repeated event changes nothing. Nothing emits the event until M7: the clinical module must put `queueTokenId` in its payload.
- **Idempotency keys are required** on recording, and only the new id is kept, so a repeat answers with the reading as it is.
- **Seed:** `db:seed` gives the clinic its own ranges (a temperature high from 37.5 °C, SpO₂ low below 94) and adds `nurse@sample-hospital.test`, who records; the sample doctor only reads.
