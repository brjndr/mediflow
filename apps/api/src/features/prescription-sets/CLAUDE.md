# Prescription sets API

What was decided for this feature's API (#394). The web side's notes are in `apps/web/src/features/clinical/CLAUDE.md` (the set bar of the prescription form) and `apps/web/src/features/drugs/CLAUDE.md` (favourites in `DrugSearch`).

- **`features/prescription-sets`** keeps named lists of medicine lines a prescriber loads into a prescription, and each doctor's favourite medicines. Behind the `clinical` module flag (no flag of its own: it is part of prescribing, and its permissions are registered under `clinical`, so a platform admin is offered no extra module), migration 0069 (`prescription_sets`, `prescription_set_lines`, `doctor_favourite_drugs`).
- **A set is shared or a doctor's own.** `owner_user_id` NULL is shared with every prescriber of the hospital; otherwise it is that member's and nobody else's. A read of another member's own set answers 404 `prescription_set_not_found`, the same as a missing set or another hospital's.
- **Three permissions, never a role name.** `prescriptionSet:read` (admin, doctor, nurse) uses sets and favourites; `prescriptionSet:manage` (admin, doctor) keeps one's own sets and one's own favourites; `prescriptionSet:manageShared` (admin) adds, changes and archives the sets shared with the hospital (403 `permission_denied` otherwise, checked in the handler with the caller's policy). A doctor can use a shared set but not change it.
- **A line is a prescription line without a patient:** `drug_id`, dose, route, frequency, days, quantity, instructions, with the limits of the `orders` table (0039) and one to 30 lines. The medicine must be one `prescribableDrug` takes at the time of saving (422 `unknown_drug`). **A medicine archived afterwards stays on the set and is flagged `drugArchived` on read, not dropped;** the web app leaves it out of what it loads and says so.
- **Loading a set creates nothing on the server.** The client adds the lines to its form, and the existing prescribing route does the checks (allergies and repeats are the client's warnings; the API refuses an unknown medicine).
- **Versioned edits.** `PATCH /prescription-sets/:id` sends only what changes with the `version` it started from (409 `conflict`); the row is locked while the versions are compared. Archiving is a PATCH; there is no DELETE. An own set may not take the name of a shared one, nor a shared set the name of another shared one (it never learns of anyone's private set), whatever the capitals, archived or not (409 `prescription_set_name_taken`).
- **Favourites change one at a time:** `PUT` and `DELETE /me/favourite-drugs/:drugId` star or unstar one medicine under an advisory lock on the person (`changeFavourite`), so two quick stars or two tabs both stay (#484); a twenty-first drops the oldest. `PUT /me/favourite-drugs` still replaces the whole list (at most 20, each once), but the web app no longer uses it.
- **Audit never carries the lines:** `create` and `update` of `prescription_set` with the set's id, and `update` of `favourite_drugs`. A set holds no patient data, but the audit is ids and codes by rule.
- **Cross-feature:** the medicine names come from `medicineLabels` of `features/drugs`, the line limits and routes from `features/clinical/index.ts` (`DOSE_MAX`, `INSTRUCTIONS_MAX`, `LINES_MAX`, `MEDICATION_ROUTES`), so there is one list of each.
