# Lab tests API

What was decided for this feature's API. Moved out of `apps/api/CLAUDE.md` (#370); Claude Code loads it when a file of this folder is read. The web side's notes are in `apps/web/src/features/lab-tests/CLAUDE.md`.

- **`features/lab-tests`** is the tests and panels the laboratory offers: how each is collected, how its result is read, and the reference ranges of a numeric test. Reference data with no patient data. Behind the `lab_tests` module flag, with `labTest:read` for those who order, collect, perform and bill, and `labTest:manage` for the admin.
- **The code and the kind never change** (a trigger): the code is the test's identity on orders and reports, and a test with results cannot become a panel.
- **A panel is an ordered set of single tests of the same hospital that are in use,** at least one and none twice, in `lab_test_components`. It has no result of its own (a check constraint: text, no unit). A trigger refuses a component that is not a single test, and the foreign keys carry the hospital.
- **A test that a panel in use is made of cannot be archived** (409 `lab_test_in_panel`), and a panel one of whose tests is archived is not restored (409 `lab_test_component_archived`): a panel in use is made of tests in use. Making a panel locks its components, in id order and single tests only (a panel named by mistake is refused without being held, so two panels that name each other cannot deadlock), and archiving locks the test, so of a panel being made and one of its tests being archived at the same moment exactly one goes through.
- **A test is charged as a laboratory service of its hospital** (`service_id`, with the hospital in the foreign key). The route refuses any other, and an archived one, with a 400, when the link is made: a link a test already has is left alone, and nothing keeps it true afterwards. The answer carries the service's name and nothing else of it, to everyone who may read the test, by decision.
- **Reference ranges are replaced as a set** (`PUT .../ranges`) and have their own version, `ranges_version`, because other people change them at other times. The trigger on `lab_tests` counts both: a statement that moves `ranges_version` leaves `version`, and any other counts `version`, also a change of a panel's components alone. Only a numeric single test has ranges (409 `lab_test_has_no_ranges`, and a trigger), and a test with ranges stays numeric and keeps its unit until they are removed (409 `lab_test_has_ranges`, and the trigger, migration 0023): the ranges are numbers in that unit.
- **An age is a value with its unit, never a count of days** (`age.ts`): a patient reaches it on the calendar day that lies that long after the date of birth. That two ranges for the same sex never both hold is a rule about every possible date of birth, so the route checks it and no constraint can. What a constraint can say about one row, it says: a limit is given, `low` is below `high`, a critical low needs a `low` and is below it, and a critical high needs a `high` and is above it, so no result is both normal and critical (#310, migration 0047). A limit is a number smaller than a thousand million either side of zero.
- **`age.ts` is a copy of the web app's** (`apps/web/src/features/lab-tests/age.ts`), because the API may not import from it, and so are its tests. `age.test.ts` reads the other two files and fails when they differ. Change both together.
- **`GET .../ranges/resolve`** answers the catalog screen's check with an age someone typed, tried as a person born on 1 January 2001. It identifies no patient. For a real patient the laboratory module (M8) uses `bandFor` with the date of birth and the date the sample was collected, on the server, and never sends either in an address.
- **Text is tidied and plain** (`core/http/text.ts`): names, units, containers and notes, as in drugs. `tidyWithin` and `tidyOptional` take the longest the text may be once tidied, because a few letters become two characters in the normal form and the database would otherwise refuse them as a 500.
- **`POST /lab-tests` accepts an Idempotency-Key** and stores the whole answer for a replay.
- **Changes are audited** (`lab_test`, `lab_test_ranges`) and emit `master.changed`.
- **Exports** from `index.ts`: `orderableLabTest`, a test or panel that is not archived with its code and name, which the clinical module places a lab order for (#86); `labTestSample`, the sample and container a test is collected in, archived or not, and `analytesOf`, what an order of a test is resulted as (the test, or each test of a panel in order) with its ranges, and `bandFor`, for the laboratory (#95).
