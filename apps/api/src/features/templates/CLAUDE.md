# Document templates API

What was decided for this feature's API. Moved out of `apps/api/CLAUDE.md` (#370); Claude Code loads it when a file of this folder is read. The web side's notes are in `apps/web/src/features/templates/CLAUDE.md`.

- **`features/templates`** is each hospital's own blank forms for a prescription, a clinical note, a consent form and a discharge summary. Behind the `templates` module flag, with `template:read` for those who write such a document, `template:manage` for the admin and `template:redact` for the one change a saved version can have.
- **Versions are append-only.** Every save of a changed name or text is the next version in `template_versions`; the ones before it are never touched. The app role has no DELETE and may UPDATE only the columns a redaction writes, and triggers hold every change to it, the owner's too: a template is added as its version 1, a version is the next number, a saved version changes only to be redacted (and the database dates that), and a template's name, number and time move only to those of a version that was saved (migrations 0028, 0029). Deleting is refused by the grant, not by a trigger: the owner can, which is how a hospital's rows are removed. `templates` keeps the name, number and time of its newest version, so the list and the rule that a name is one template of its kind (409 `template_name_taken`) are comparisons on a column.
- **A save names the version it was made from** (`expectedVersion`, 409 `conflict`), with the template locked. Saving what the newest version already has makes no version. An archived template takes none (409 `template_archived`). A template has at most 500 versions (409 `template_version_limit`): every answer lists them. The last one is kept for whoever holds `template:redact`, so that what was typed by mistake into version 499 can still be replaced and then removed. What is typed into version 500 itself cannot be: the template is then archived and a new one made, and removing that text is a job for the database's owner.
- **A redaction (#292) removes the name and the text of one older version,** for when something was typed into a template that should not be kept. `POST /templates/{id}/versions/{n}/redact`. The row stays, with its number, who saved it and when, and who redacted it, when and why. **The reason is from a list, never free text:** a typed reason could repeat what is being removed, and would go where no redaction reaches. The newest version is the template as it is used, so it is not redacted (409 `template_version_current`, and the trigger): a corrected version is saved first. Twice changes nothing. It cannot be undone. A document made from the version (M7) keeps its own copy of the text.
- **Nothing of a template's text is kept anywhere else,** so that a redaction removes all of it: the audit entry carries the template's id (which version, by whom, when and why are on the version's own row), and the event the id, the version number and the reason; `POST /templates` keeps of its answer only the new template's id (`idempotent: { body: 'none' }` with `request.idempotentId`) and answers a repeat from the template as it is then; every answer is `Cache-Control: private, no-store` (the core default, which these routes must never override), so no browser keeps a copy; and an unknown placeholder is not named in the refusal. What is left is outside the application: for 24 hours the idempotency key holds a hash of the create request, which cannot be read back but can confirm a guess, and the database keeps the old row until it is vacuumed and in its backups for as long as those are kept. Reading a version is not audited: a template is meant to hold no patient data.
- **The text is the web app's rich text document,** reduced to its allowlist on the way in and again on the way out (`core/http/rich-text.ts`), and stored as `jsonb`. The database gives the keys of a stored document in its own order, so two texts are compared after both are reduced. A text with a NUL or half a surrogate pair is refused: the database would refuse it as a 500. So is one nested tens of thousands of levels deep, which could not be written out again.
- **Each kind knows a fixed list of placeholders** (`placeholders.ts`), and a text with any other is refused (400). A placeholder is read only within one run of text.
- **`core/http/rich-text.ts` and `placeholders.ts` are copies of the web app's** (`shared/ui/rich-text/document.ts`, `features/templates/placeholders.ts`), because the API may not import from it. `copies.test.ts` fails when either differs from its original. Change both together.
- **Whoever changes a template needs `template:read` as well,** because the answer is the template. A `kind` sent with a save is not read: the kind never changes (a trigger).
- **The name is tidied and plain** (`core/http/text.ts`), as in drugs and lab tests.
- **Changes are audited** (`create`, `update`, `archive`, `restore`, `redact` on `template`) and emit `master.changed`.
