# How a session ends in the web app

Moved out of the root `CLAUDE.md` (#370), which keeps the rule; Claude Code loads this file when a file of this folder is read. Read it before changing or using what is here.

the idle time comes from the tenant config (`auth.idleTimeoutMinutes`, 30 minutes when absent). A dialog asks during the last minute, with focus on staying signed in so that a key pressed out of habit never ends the session (Escape stays too), and from then on only its buttons count as activity. Activity and sign-in or sign-out are shared between tabs over a `BroadcastChannel` that carries fixed words and no data. Every ending (sign-out, idle, another tab, a 401 from the server) goes through `endSessionLocally`, which drops all cached data and client state before the login page shows, and after a sign-out or an idle timeout the address of the open screen is not kept for whoever signs in next (after a 401 it is, since the user was at work).

The idle warning stays on its own native `<dialog>` and does not move onto the shared `Dialog` (#372): it is a small centred box that already fits a phone, it is mounted at the app root where it must work before anything else has loaded (no extra chunk), and it needs a focus order of its own (stay signed in first, Escape stays) and to count only its buttons as activity.

**The code step at sign-in** (`features/auth/components/LoginPage.tsx`, #252) drops the held email and password after `MFA_STEP_TIMEOUT_MS` (5 minutes, restarted by each attempt) and shows why. Recovery codes (`RecoveryCodes.tsx`, setup and replacement) hold the person on the page until they tick that the codes are saved: `useLeaveGuard` asks the browser to confirm closing or reloading and stops clicks on links before the router sees them (there is no data router, so no blocker; the browser's back button cannot be held). Copied codes are cleared from the clipboard after a minute and when the screen closes. `/security` for a person with an authenticator offers replacing recovery codes and turning it off (`ManageAuthenticator.tsx`), each asking again for the password and an app code; "turned off" travels in router state so it survives the page being rebuilt while the session reloads.
