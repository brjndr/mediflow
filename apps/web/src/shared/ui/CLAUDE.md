# Shared building blocks

Moved out of the root `CLAUDE.md` (#370), which keeps the rule; Claude Code loads this file when a file of this folder is read. Read it before changing or using what is here.

Build lists, charts, forms, notes and calendars from these, and do not import the underlying libraries in feature code. Working examples are at `/examples` in dev.

- `data-grid`: `DataGrid` for every tabular list. A table where there is room and cards on a narrow screen, with no work from the screen. Server-side sorting and cursor paging, masked columns (`maskPhone`, `maskMrn` from `shared/utils/mask`), columns and row actions gated by `requires`, rows virtualised past 100. Pass `total` when the server gives one, so a screen reader hears a row's place in the whole list; the grid says loading, the sort and nothing found in its own polite live region, and leaves how many rows there are to the screen's own status message (#340).
- `charts`: `TimeSeriesChart` and `CategoryBarChart`. They load on demand, take colours from theme tokens, and carry a data table for screen readers. Each is a figure named by its title and a one-line `summary` (the count, highest and lowest when the screen gives none), and "Show as table" shows the same table on screen in place of the picture (#342).
- `form`: `useZodForm`, `Form`, the field components and `SubmitButton`. Validation messages are translation keys. `useFieldValue` gives what another field holds, for a field that depends on it; `useSetFieldValue` sets a field from code (a list built by picking); `useFieldError` gives a field's message to a field drawn by hand, and `useFieldFocusRef` lets a failed submit focus it in the order of the form; `useFieldRows` holds a list of rows whose fields are named by position (`rows.0.low`).
- `print-sheet`: `PrintSheet`, a document to print (#89). It draws its children into a box of its own under `<body>`, hidden on screen and the only thing on paper (the print rules at the end of `index.css`), opens the print dialog once its images are ready and calls `onDone` when the dialog closes. Mount it with a new `key` per print, after whatever must happen first (the audit). `className` replaces the page's padding and type for something smaller than a page, such as a sample's label (#90), which also sets its own `@page` size. The letterhead is `Letterhead` from `@/tenancy`: the hospital's logo and name, and its address, phone and registration number when the tenant config has them (#397).
- `rich-text`: `RichTextEditor` (loads on demand) and `RichTextView`. Rich text is a sanitized JSON document (`sanitizeRichText`), never HTML.
- `calendar`: `Calendar`, a day or week time grid (react-big-calendar, MIT, loads on demand in the `calendar` chunk). It takes UTC instants and the hospital's timezone and locale, and draws the hospital's clock whatever the browser's timezone; the visible range and week helpers are in `calendar/zoned`. The screen draws its own toolbar and asks the server for the visible range only. The week view is for desktop width (`useIsDesktop` from `shared/hooks`). The time grid is one Tab stop worked with the arrows, Home, End, Page Up and Page Down (#341); a block is named by what it shows (its start and title) first, so the name holds the visible text (WCAG 2.5.3, #386), then its end, its day and its `label`, the detail the title has no room for, and is marked by its `icon`; and a screen may let a free time be chosen (`onSelectSlot`) and the keys move the range (`onNavigate`). With `resources` (a day with a column for each, #331) the columns are the resources: events carry a `resourceId`, `onSelectSlot` and `canSelectSlot` get it as a third argument, Left and Right walk the columns, and Page Up and Page Down change the day through `onNavigate`. The week is not drawn with them, and a screen offers it at desktop width only.
- `confirm-dialog`: `ConfirmDialog`, a question before something that cannot be undone with one click (#129): a modal on the native `<dialog>` with `role="alertdialog"`, Cancel first in focus (or the first `data-autofocus` field in its children), Escape cancels, and it is nearly the full width on a phone. Give it `onConfirm`, or `confirmForm` (the id of a `Form` in its children, which takes an `id`) to confirm by submitting that form. Its content is mounted only while open, so a form inside starts empty. The browser returns focus to the control that opened it; when that control is gone, move focus on with `focusIfLost`.
- `server-search`: `ServerSearch`, the combobox for a catalog the server searches (#402). `ServiceSearch`, `LabTestSearch`, `CodeSearch` and `DrugSearch` are thin wrappers that pass it their own query hook, option text, messages and permission check; build a new catalog search the same way. It is a Radix-free combobox worked from the input (`aria-activedescendant`, an option never takes focus): arrows wrap, Escape closes, Enter never submits the form and never picks a result that belongs to earlier text, results are announced in an always-present status line, and targets are 44 px under `pointer-coarse`. The wrapper passes `useSearch(typed, enabled)` (a named `use…` function, called as a hook, `typed` already debounced by `useDebouncedValue` from `shared/hooks/use-debounced-value`, which every feature uses instead of its own copy), `available` (module on and permission held), `messages`, `optionKey`, `renderOption` and `onChoose(option, reset)`; optional `invalid`, `describedBy`, `searchOnEmpty` (offer what the server gives before anything is typed, as favourites), `useIdle` (a screen's own list while nothing is typed) and `notice`. The search term goes in the body of a `POST …/search`, never an address. `PatientSearch` and `AllergenField` are not on it yet (`PatientSearch` also takes `required`, `focusOnMount` and `type="search"`). Example: the form example at `/examples/form`.
- `dialog`: `Dialog`, the modal for a short form or a confirmation with a field (#372). Built on `@radix-ui/react-dialog` (MIT; about 10 kB gzipped with its focus and scroll-lock helpers, in the route chunks that use it), chosen over the native `<dialog>` of the drawer and `ConfirmDialog` because CLAUDE.md asks for Radix on every dialog and Radix gives the focus trap, the inert background and `aria-labelledby`/`describedby` for free. Controlled: `open`, `onOpenChange`, `title`, `closeLabel`, optional `description`, `footer`, `size` (`sm`, `md`, `lg` from `md` up) and `busy`. The whole screen below `md` (768 px), a centred box from there; the header (title and close) and footer (actions) stay in view and the body scrolls with `scroll-padding`. Focus starts on the first `data-autofocus` element or field of the body, else on the title (a confirmation), and goes back to the control that opened it (the caller uses `focusIfLost` if that control is gone). `busy` keeps it open on Escape, a click outside and Close. A form in the body takes an `id` and a button in the footer submits it with `form="<id>"`; `SubmitButton` needs the form's context, so in the footer use `Button type="submit"` with `aria-disabled` while saving. `ConfirmDialog` stays for the plain question. Example: `/examples/dialog`.

## Visual language (#707)

Tokens in `index.css`, exposed to Tailwind in `@theme inline`; all derived with `color-mix()` from `--background`, `--primary` and the status colors, so a hospital that sets only its primary color re-themes them (nothing here is in `THEME_TOKENS`, and no raw hex or `rgb()` is allowed in them; `tenancy/visual-tokens.test.tsx` checks it and the contrast).

- **Base:** soft cards and bento layouts. `bg-page` for the page tint (opt in; `bg-background` is unchanged), `shadow-soft` for a card, `shadow-raised` for something lifted.
- **Neumorphism** (`shadow-raised` with `shadow-inset`) only on the switch, the search field and the ring gauge. Never on forms, tables or clinical data.
- **Glass** (translucent, blurred) only on the desktop sidebar, with a solid `bg-card` fallback where `backdrop-filter` is missing or the user asks for less transparency.
- **Status** is always color plus icon plus word. Tones: `bg-success-soft text-success-soft-foreground`, likewise `warning`, `destructive` and `info`; each pair is at least 4.5:1 in light and dark.
- **Brand gradient:** `bg-brand-gradient` with `text-primary-foreground`. The second stop moves away from the text color, so contrast with `--primary-foreground` can only rise from the first stop (itself guaranteed by `themeFromBrandColor`); no flat fallback is needed.
