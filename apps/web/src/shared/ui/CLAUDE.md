# Shared building blocks

Moved out of the root `CLAUDE.md` (#370), which keeps the rule; Claude Code loads this file when a file of this folder is read. Read it before changing or using what is here.

Build lists, charts, forms, notes and calendars from these, and do not import the underlying libraries in feature code. Working examples are at `/examples` in dev.

- `data-grid`: `DataGrid` for every tabular list. A table where there is room and cards on a narrow screen, with no work from the screen. Server-side sorting and cursor paging, masked columns (`maskPhone`, `maskMrn` from `shared/utils/mask`), columns and row actions gated by `requires`, rows virtualised past 100. Pass `total` when the server gives one, so a screen reader hears a row's place in the whole list; the grid says loading, the sort and nothing found in its own polite live region, and leaves how many rows there are to the screen's own status message (#340).
- `charts`: `TimeSeriesChart` and `CategoryBarChart`. They load on demand, take colours from theme tokens, and carry a data table for screen readers. Each is a figure named by its title and a one-line `summary` (the count, highest and lowest when the screen gives none), and "Show as table" shows the same table on screen in place of the picture (#342). Line charts fade a fill from the series colour, bars are rounded and fade too (gradients of `var(--primary)`, so brand and dark mode follow). `emphasize` (a bar chart, a label) draws one bar in full colour with its value written above, softens the rest, and names it in the summary and the table, so it is never colour alone (#711).
- `form`: `useZodForm`, `Form`, the field components and `SubmitButton`. Validation messages are translation keys. `useFieldValue` gives what another field holds, for a field that depends on it; `useSetFieldValue` sets a field from code (a list built by picking); `useFieldError` gives a field's message to a field drawn by hand, and `useFieldFocusRef` lets a failed submit focus it in the order of the form; `useFieldRows` holds a list of rows whose fields are named by position (`rows.0.low`).
- `print-sheet`: `PrintSheet`, a document to print (#89). It draws its children into a box of its own under `<body>`, hidden on screen and the only thing on paper (the print rules at the end of `index.css`), opens the print dialog once its images are ready and calls `onDone` when the dialog closes. Mount it with a new `key` per print, after whatever must happen first (the audit). `className` replaces the page's padding and type for something smaller than a page, such as a sample's label (#90), which also sets its own `@page` size. The letterhead is `Letterhead` from `@/tenancy`: the hospital's logo and name, and its address, phone and registration number when the tenant config has them (#397).
- `rich-text`: `RichTextEditor` (loads on demand) and `RichTextView`. Rich text is a sanitized JSON document (`sanitizeRichText`), never HTML.
- `calendar`: `Calendar`, a day or week time grid (react-big-calendar, MIT, loads on demand in the `calendar` chunk). It takes UTC instants and the hospital's timezone and locale, and draws the hospital's clock whatever the browser's timezone; the visible range and week helpers are in `calendar/zoned`. The screen draws its own toolbar and asks the server for the visible range only. The week view is for desktop width (`useIsDesktop` from `shared/hooks`). The time grid is one Tab stop worked with the arrows, Home, End, Page Up and Page Down (#341); a block is named by what it shows (its start and title) first, so the name holds the visible text (WCAG 2.5.3, #386), then its end, its day and its `label`, the detail the title has no room for, and is marked by its `icon`; and a screen may let a free time be chosen (`onSelectSlot`) and the keys move the range (`onNavigate`). With `resources` (a day with a column for each, #331) the columns are the resources: events carry a `resourceId`, `onSelectSlot` and `canSelectSlot` get it as a third argument, Left and Right walk the columns, and Page Up and Page Down change the day through `onNavigate`. The week is not drawn with them, and a screen offers it at desktop width only.
- `confirm-dialog`: `ConfirmDialog`, a question before something that cannot be undone with one click (#129): a modal on the native `<dialog>` with `role="alertdialog"`, Cancel first in focus (or the first `data-autofocus` field in its children), Escape cancels, and it is nearly the full width on a phone. Give it `onConfirm`, or `confirmForm` (the id of a `Form` in its children, which takes an `id`) to confirm by submitting that form. Its content is mounted only while open, so a form inside starts empty. The browser returns focus to the control that opened it; when that control is gone, move focus on with `focusIfLost`.
- `server-search`: `ServerSearch`, the combobox for a catalog the server searches (#402). `ServiceSearch`, `LabTestSearch`, `CodeSearch` and `DrugSearch` are thin wrappers that pass it their own query hook, option text, messages and permission check; build a new catalog search the same way. It is a Radix-free combobox worked from the input (`aria-activedescendant`, an option never takes focus): arrows wrap, Escape closes, Enter never submits the form and never picks a result that belongs to earlier text, results are announced in an always-present status line, and targets are 44 px under `pointer-coarse`. The wrapper passes `useSearch(typed, enabled)` (a named `use…` function, called as a hook, `typed` already debounced by `useDebouncedValue` from `shared/hooks/use-debounced-value`, which every feature uses instead of its own copy), `available` (module on and permission held), `messages`, `optionKey`, `renderOption` and `onChoose(option, reset)`; optional `invalid`, `describedBy`, `searchOnEmpty` (offer what the server gives before anything is typed, as favourites), `useIdle` (a screen's own list while nothing is typed) and `notice`. The search term goes in the body of a `POST …/search`, never an address. `PatientSearch` and `AllergenField` are not on it yet (`PatientSearch` also takes `required`, `focusOnMount` and `type="search"`). Example: the form example at `/examples/form`.
- `dialog`: `Dialog`, the modal for a short form or a confirmation with a field (#372). Built on `@radix-ui/react-dialog` (MIT; about 10 kB gzipped with its focus and scroll-lock helpers, in the route chunks that use it), chosen over the native `<dialog>` of the drawer and `ConfirmDialog` because CLAUDE.md asks for Radix on every dialog and Radix gives the focus trap, the inert background and `aria-labelledby`/`describedby` for free. Controlled: `open`, `onOpenChange`, `title`, `closeLabel`, optional `description`, `footer`, `size` (`sm`, `md`, `lg` from `md` up) and `busy`. The whole screen below `md` (768 px), a centred box from there; the header (title and close) and footer (actions) stay in view and the body scrolls with `scroll-padding`. Focus starts on the first `data-autofocus` element or field of the body, else on the title (a confirmation), and goes back to the control that opened it (the caller uses `focusIfLost` if that control is gone). `busy` keeps it open on Escape, a click outside and Close. A form in the body takes an `id` and a button in the footer submits it with `form="<id>"`; `SubmitButton` needs the form's context, so in the footer use `Button type="submit"` with `aria-disabled` while saving. `ConfirmDialog` stays for the plain question. Example: `/examples/dialog`.

## Visual language (#707)

Tokens in `index.css`, exposed to Tailwind in `@theme inline`; all derived with `color-mix()` from `--background`, `--primary` and the status colors, so a hospital that sets only its primary color re-themes them (nothing here is in `THEME_TOKENS`, and no raw hex or `rgb()` is allowed in them; `tenancy/visual-tokens.test.tsx` checks it and the contrast).

- **Base:** soft cards and bento layouts. `bg-page` for the page tint (opt in; `bg-background` is unchanged), `shadow-soft` for a card, `shadow-raised` for something lifted.
- **Neumorphism** (`shadow-raised` with `shadow-inset`) only on the switch, the search field and the ring gauge. Never on forms, tables or clinical data.
- **App shell (#709, recoloured in #1119):** `.shell-bg` (page wash, now three accent hues) on the shell root, `.shell-sidebar` (glass at `lg` and up: blur 12 px behind `@supports`, solid `--card` under `prefers-reduced-transparency`), active nav item filled with the brand gradient (not color alone: bold and `aria-current`). The shell has no search, so no `SearchInput` in the header.
- **Glass** (translucent, blurred) only on the desktop sidebar, with a solid `bg-card` fallback where `backdrop-filter` is missing or the user asks for less transparency.
- **Status** is always color plus icon plus word. Tones: `bg-success-soft text-success-soft-foreground`, likewise `warning`, `destructive` and `info`; each pair is at least 4.5:1 in light and dark.
- **Brand gradient:** `bg-brand-gradient` with `text-primary-foreground`. The second stop moves away from the text color, so contrast with `--primary-foreground` can only rise from the first stop (itself guaranteed by `themeFromBrandColor`); no flat fallback is needed.
- **Components (#708):** `card` (`Card` variants `soft`, `raised`, `brand`; `asChild` styles a `section`; `StatCard` is built on it), `status-badge` (`StatusBadge`, tones success, warning, danger, info, neutral: always an icon and the label, an optional `icon` replaces the tone's), `switch` (`Switch` on `@radix-ui/react-switch`, MIT; `aria-disabled` for busy), `ring-gauge` (`RingGauge`, `role="img"` named with its value), `search-input` (`SearchInput`, an inset `type="search"` field with a magnifier; name it with a label) and `Button variant="brand"`. Example: `/examples/visual`.
- **Core screens (#713):** a status shown as a chip is a `StatusBadge` with a tone map beside its feature (`appointments/components/status.ts`, `billing/lib/status-tone.ts`), never palette classes. Print sheets keep `border-black`: paper is black on white whatever the brand color.
- **Checked (#714):** every route passes axe with contrast in light and dark (`A11Y_DARK=1`); the landing page passes under four brand colors in light. Dark has no switch in the app. `themeFromBrandColor` accepts a color by its contrast on white and also returns `primary-dark` (`darkCounterpart`: the color lightened, same hue, until it has 4.5:1 on the dark card) and `primary-dark-foreground`; `.dark` in `index.css` uses them for `--primary`, `--ring` and `--primary-foreground` with `!important`, because the brand is written inline on the root (#729). The four colors pass axe in dark too (`A11Y_DARK=1`). `prefers-reduced-motion` and `prefers-reduced-transparency` (solid sidebar) are in `index.css`, and print is untouched (`.shell-bg` has no background in print).

- **Colourful pass (#1119).** Still derived from `--primary` and `--background` alone:
  - **Tinted neutrals:** `--secondary`, `--muted`, `--accent`, `--border` and `--input` are mixes of the brand, not greys. `--primary-soft` is a brand tint, and `--primary-ink` (the brand pulled toward `--foreground`) is the text set on it. The test checks 4.5:1 for that pair under seven brand colours in light and dark, and for muted text on `--muted` and `--page`. The light `--destructive` went from L 0.58 to 0.53, so red text stays 4.5:1 on a striped row or a tint (axe caught it on inventory and emergency). The dark `--primary-soft` is 22%, the most that red text on it allows.
  - **Five accent hues:** `--accent-1` to `--accent-5` (and `-soft`) turn the brand round the hue wheel with `oklch(from …)` at a fixed lightness. They are decorative only, for icon chips and tile edges, never for text and never the only sign of anything.
  - **Buttons have a background and depth in every variant:** `default` and `brand` use the gradient with `shadow-button` (a shadow in the brand colour and a top highlight) and lift on hover. `outline`, the everyday action, is `bg-primary-soft text-primary-ink` with a brand border and `shadow-tinted`. `destructive` uses `bg-danger-gradient` (toward black, away from its white text). `ghost` takes the ink, and `DataGrid` row actions are `outline`.
  - **Links that act:** `shared/ui/button.tsx` also exports `actionLink` (the screen's main action, such as "Register a patient"), `secondaryLink` (other actions and ways back), `subNavLink` (a screen group's tabs: pills, the current one filled and bold) and `textLink` (a record's name in a row). A standalone action is never plain underlined text; a link inside a sentence keeps its underline and takes `text-primary-ink`. They are in `button.tsx`, not a file of their own, which was one more request on nearly every route; for the same reason `vite.config.ts` puts the widgets' heading icons in the home widgets chunk.
  - **Shell:** a gradient strip along the top of the header, the user's initials on a gradient avatar (`aria-hidden`, the name beside it is the link's text), and nav items with an icon chip in the accent hues in turn. The current item is filled with the gradient, bold and `aria-current`.
  - **Home:** a gradient banner holds the `h1`. Its circles are tinted away from the text colour, as the gradient is. Each tile has a top edge in an accent hue in turn (`nth-child` on the grid), and `StatCard` and `WidgetHeading` take `icon` and `accent` for a chip beside the title. `WidgetLink` is a widget's foot link, a tinted pill with an arrow.
  - **Surfaces:** the `DataGrid` table sits on a card with a gradient header row (opaque, so it can stick) and striped rows, and its cards have a brand left edge. Form fields are `bg-card` with a brand border on hover and focus. A dialog's header is `bg-primary-soft` with a brand top edge. Native checkboxes, radios and meters take `accent-color: var(--primary)`. The page wash mixes three accent hues at 6 to 14%.
- **Type (#1123):** Inter for body text (`--font-sans`, so every Tailwind `font-sans` and the page) and Space Grotesk for headings and figures (`--font-display`, the `font-display` utility), self-hosted from `@fontsource-variable` (SIL OFL; no font CDN, for the CSP and privacy). Each is one variable woff2, Latin subset only, `font-display: swap` (Inter about 48 kB, Space Grotesk about 22 kB); nothing is preloaded, since the file paths are hashed and text paints at once in the system font. Both tokens are in a plain `@theme` block, so they exist as variables on `:root`. `h1` and `h2` take the display face in the base layer, except inside a print sheet; their sizes stay with each screen. Big figures add `font-display` and one step larger from `md` (`Stat`: `text-2xl md:text-3xl`; a widget's headline figure `text-3xl md:text-4xl`). Under `:lang(hi)` headings and `.font-display` put the Devanagari font after Space Grotesk (unlayered, to beat the utility).
- **Home banner (#1123):** a greeting for the part of the day (before 12, before 17, after) and the hospital's date in full (`format.fullDate`, `<time dateTime>` from `todayIn`), both from the hospital's timezone (`hourIn` in `shared/utils/timezone.ts`), around the `h1`. The development "API status / Recheck" line is gone, and `useHealth` with it (`fetchHealth` stays for the client tests).
- **Theme switch (#730):** `app/ThemeSwitch.tsx` in both shell headers cycles light, dark and system. The choice is a theme name in `localStorage` (`mediflow.theme`, no PHI; `shared/lib/color-scheme.ts`), applied before first paint by the inline script in `index.html` (keep the two in step) and followed live for `system`. Print CSS is unchanged.

## Hindi (#767)

- Font: `Noto Sans Devanagari Variable` (`@fontsource-variable`, SIL OFL), declared in `index.css` with the Devanagari subset only and its `unicode-range`, used first under `:lang(hi) body` only (an override of `--font-sans` putting it first for every language widened phone pages in CI). Latin is in Inter since #1123. The browser fetches the file (about 50 kB) only when a page shows Devanagari, so English pages never fetch it.
- Dates, numbers and money under `hi-IN` come from the same tenant formatters (`Intl`): Latin digits, lakh grouping, the rupee sign.
- `e2e/hindi.spec.ts` opens main screens in Hindi (`?mockUser=<id>&mockLanguage=hi`) at 320 and 360 px with axe and the no-sideways-scroll check.
- `e2e/hindi.spec.ts` also walks every registered route in Hindi at 320 and 360 px (#770), reusing the route list and record finders in `e2e/routes.ts` (shared with `a11y.spec.ts`). Found and fixed: the billing list's links wrapped below 24 px of target size. Routes of features without Hindi strings yet fall back to English per key (a long `i18n.missing_key` list in the dev console) and still pass.
- `app/i18n.ts` redraws on `added` resources: a feature with no Hindi file is ready before its English fallback arrives, and without the redraw a label showed its key.

## Native selects and file inputs (#1135)

`index.css` (base layer) gives every `select` and `input[type='file']` `min-width: 0; max-width: 100%`, so a long option or file name cannot widen a phone page. A label around one that is a flex or grid item still needs `min-w-0` itself.
