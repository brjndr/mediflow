# Medical records desk (web): module notes

What was decided for the records department's tools (MR-04, #192). The root `CLAUDE.md` wins where the two disagree.

- **Three routes, one navigation entry** ("Medical records", `medicalRecord:read`) behind the new `records` switch: `/records` (incomplete records), `/records/coding` (coding queue), `/records/requests` (record request log, `recordRequest:read`). `RecordsNav` switches between them and shows each only to the permission that opens it. Works at every width (`DataGrid`).
- **API built (#570)**, and the endpoints run on the mock too (`GET /records/incomplete`, `GET /records/coding-queue`, `POST /records/coding-queue/{diagnosisId}/code`, `GET` and `POST /record-requests`, `POST /record-requests/{id}/close`; the planned entries are gone, the real ones are in `api.openapi.json`) in `mocks/handlers/records.ts`. The server must work out the gaps itself (unsigned note, no diagnosis, no discharge summary for an inpatient stay, no signed consent for a procedure); the screen only lists them. Permissions to seed: `medicalRecord:read`, `medicalRecord:code`, `recordRequest:read`, `recordRequest:manage` (admin; a records clerk role is a hospital's own to create).
- **Coding** picks an ICD-10 code from `CodeSearch` (server search, never typed free) and sends the diagnosis version read; a conflict is refused with a message and the list is read again. Coding again replaces the code (API audits it).
- **Request log:** a closed request (fulfilled or declined, with a note) is never changed; an open one past its due day says "Open, overdue" in words. Names, purposes and notes travel in bodies only, never in an address. Fulfilling a request does not release the record itself: printing or sending a copy is a later step.
- **Assigning (#571):** "Assign to a doctor" on an incomplete record (`medicalRecord:assign`, `POST /records/incomplete/{encounterId}/assign`, `doctorId` null takes it off), a doctor picked with `useDoctorOptions`; the list shows "Assigned to". It is a note for the desk, nothing contacts the doctor.
- **Dashboard (#571):** `RecordsWidget` in `dashboard.widgets`, the count of incomplete records (the `total` of a one-row page), for `medicalRecord:read`.
- **Filter by patient (#987):** `GET /record-requests?patientId=` (an id, never a name) narrows the log; the screen picks the patient with `PatientSearch` and clears it with "Show all patients". It combines with the state filter and the count.
- **Covering letter (#571):** a fulfilled request has "Print covering letter" (`PrintSheet`, `RequestLetter`): who asked, for whom, why, who closed it and when. It holds no clinical content, so it is drawn from the row and not audited; releasing the record itself is still by hand.
- **Correction requests (#191, API #556):** `/records/corrections` (`correction:read`, scope all; pending first, "All requests" to widen) and a "Corrections" tab on the patient screen (`patient.detail.tabs`, `correction:read`, the patient's own list through `GET /patients/{id}/correction-requests`). Both are `CorrectionsGrid`. A correction is a request with its author and reason, never a silent edit: "Request a correction" (`correction:request`) says what should change and why, for the patient record; "Approve" and "Reject" (`correction:decide`) take a reason and the version read. The author cannot decide their own (403 `second_person_required`, said in words), and approving overwrites nothing: on `correction.approved` the API adds an append-only amendment (#1179), and the "Record" column says "Being added", "Amendment added" or "Not added: record gone or retired" (`appliedAt`, `applyOutcome`). The amendment is not shown on the patient, visit or document screens yet. Not built: asking for a correction to a visit or a document (the API takes both, but picking one needs a list from `clinical` and `documents`, which this feature may not import), and the author's name (the API gives an id only).
- **Not built:** a deficiency reminder (nothing contacts staff yet), exporting the log (#571 split out: a stored export by a job, as the reports), a fee for copies (billing, split out).
