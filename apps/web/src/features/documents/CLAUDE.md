# Documents (web): module notes

What was decided for the patient document store's screen (MR-01, #189). The API is `apps/api/src/features/documents` (BE-29, #194); read its `CLAUDE.md` too. The root `CLAUDE.md` wins where the two disagree.

- **A tab, nothing else.** `DocumentsTab` is contributed to `patient.detail.tabs` (`document:read`, behind the `documents` switch). No route, no navigation item. It shows the patient's documents newest first, a page at a time, with a category filter and "Show retired documents" (both sent to the server).
- **Upload is two steps, as the API has them:** `POST /patients/{id}/documents` (idempotency key kept per identical body) answers a signed `uploadUrl`; `sendFile` then PUTs the bytes to it after the API base (`/api` + the address), with no session. Type (JPEG, PNG, PDF) and size (25 MB) are checked in the form first, the API checks again plus the first bytes. A file is `scanning` until the malware scan job clears it: the row says so and "Open" stays inert (`aria-disabled`) until it is `clean`.
- **A blocked file is told, not only listed (#564):** while any listed file is `pending` or `scanning` the list is read again every `SCAN_POLL_MS`; a file seen waiting that comes back `infected` or `failed` is announced in the status line (`blocked.*`). A file already blocked when the tab opened is only a row.
- **Opening a file** asks `GET /documents/{id}/download-url` (audited by the API as an `export`; every listing is audited as `read`) and opens the signed link in a new window. The link is never stored or shown.
- **Retire, never delete:** a reason and the version read (`document:retire`). A retired document stays and can still be opened.
- **Categories are the "types"**; the API has no free tags. A tag field would need a contract change.
- **Mock:** `mocks/handlers/documents.ts` (three documents on `pth_00001`, `finishMockScan`, `mockDocumentAudit`). Not built here: consents and certificates as their own records (done in `features/consents`, MR-02), patient merge (#191).

- **Retention rules screen (#561):** route `/document-retention` and a navigation item (`documentRetention:read`; "Change" needs `documentRetention:manage`), same `documents` switch. One list of the categories the API returns (at most seven, no paging) in a `DataGrid`; "Change" opens an inline form: years (1 to 100) or "Keep for ever" (`years: null`, which deletes the rule). A category kept for ever opens with the box ticked, and the years count only while it is clear. The page says a rule applies to documents attached from now on. Legal holds have no screen yet.

- **Legal holds (#628):** placed from the Documents tab (`documentRetention:manage`): "Hold" on a row holds that document, "Hold all documents" holds every document of the patient, later ones too; both need a reason. The active holds (`GET /legal-holds`, newest first, a page at a time) are a section under the retention rules on `/document-retention`, with "Release" after a confirmation. No new route or navigation item. Each document says `held` (#672) and the tab's State column shows an "On legal hold" badge beside the status; placing or releasing a hold refreshes the documents too. Not done: a place on the medical records desk (it has no documents list yet), and a hold's placer or release history.

- **Documents of a visit (#562):** a "Documents" button in `encounter.detail.actions` (`document:read`) opens a panel under the actions with the files linked to that visit (`GET .../documents?encounterId=`, new on the API) and "Add document" (`document:upload`) sends `encounterId` with the upload. Nothing is read until opened. The documents tab still lists all of the patient's files.
