# Emergency (web): module notes

What was decided for ER-01 (#171). The root `CLAUDE.md` wins where the two disagree. The API exists (BE-26, #175, `apps/api/src/features/emergency/CLAUDE.md`); the mock in `mocks/handlers/emergency.ts` follows it. The API also has `POST .../unidentify` (undo a link within 24 hours) with no screen yet.

- **One route, one nav entry** ("Emergency", `emergency:read`, `/emergency`, order 26) behind the `emergency` switch. A `DataGrid` board (cards on a phone) read again every 10 seconds, ordered by the server: untriaged arrivals first, then category 1 to 5, then the longest wait.
- **Permissions:** `emergency:register` (register an arrival, link an unidentified patient to a record), `emergency:triage` (set or change the category). Row actions use `requires`, so they are absent without the permission.
- **Quick registration** needs the complaint and how the patient came; everything else has a default (sex "not known", walk-in, not triaged). Two modes: **unidentified** (optional description and approximate age; the server issues a temporary ID, `tempId`, e.g. ER-0042, which stays on the case after identification) and **patient on record** (`PatientSearch`, only the id is sent). The category can be set at the same time.
- **Identify later** (`/identify`) links an unidentified case to a patient; once only (409 `already_identified`). Merging two records is the patients module's job, not this one's.
- **Timers:** the waiting time is minutes since arrival, drawn from a clock that ticks every 15 s (`useNow`). `TARGET_MINUTES` (1: immediate, 2: 10, 3: 30, 4: 60, 5: 120) is a fixed default in `schemas.ts`; past it a waiting patient is marked "Overdue" with a word and an icon, never colour alone. A hospital's own targets are a setting for later. Untriaged patients have no target.
- **Triage fields:** only the category (1 to 5) is captured here. Vitals at triage are not captured here; the existing `triage` module's vitals take a queue token, not an emergency case.
- **Idempotency and conflicts:** every write sends one key per identical body; triage and identify send the `version` read, and a 409 says "someone else changed this first".
- **Care and disposition (ER-02, #172)** are against the real API. The first column of the board links to `emergency/:caseId` (`routes/CaseCare.tsx`, `emergency:read`). There: **Start treatment** (`emergency:care`, waiting to in treatment), **observation notes** (`NotesPanel`, append-only, a note or an assessment, also while the patient is unidentified), **rapid orders** and **Decide disposition** (`emergency:dispose`).
- **Rapid orders are the clinical module's panels.** "Prepare orders" opens the case's `er` encounter (needs the patient on record; unidentified patients get a hint to link them first) and `EncounterOrders` (exported by `features/clinical`) shows the lab, imaging and procedure panels on it. Placing an order needs `order:create` (doctor and admin; a nurse can read and write notes but not order). The consultation screen is not linked for an `er` encounter: the API refuses closing it from there (409 `managed_by_emergency`).
- **Disposition** (`DispositionDialog`) is final: discharge, admit, refer (destination needed) or expired (time of death on the hospital's clock). Admit needs the patient on record, and an admitting doctor: the caller's own profile, else the select of doctors (`useDoctorOptions`). It opens the inpatient admission (type `emergency`, no bed: assign one on the bed board) and the case shows "See the admissions list"; the emergency record stays as it was. After it the case is read only, a record of how the patient left.
- **Not built:** medico-legal flags (ER-03), choosing a bed at admission, marking the patient deceased on their record, a doctor-only filter, a push stream for the board (it polls), sound alerts, a waiting-room display.
