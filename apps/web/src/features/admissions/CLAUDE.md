# Admissions (web): module notes

What was decided for this module in the web app. The root `CLAUDE.md` wins where the two disagree. The API is described in `apps/api/src/features/admissions/CLAUDE.md`; the beds themselves (wards, rooms, categories) are the `wards` module.

## What exists

**The bed board (#151)** at `/beds`, behind the `admissions` switch and `admission:read` (the API also needs `wards` on). Every bed in use as a `DataGrid` (cards on a phone, bed number as the title), by ward name and bed number, from `GET /beds/board` one server page at a time, filtered by ward and status. The occupant's name is shown and the MRN masked. A status is a word and an icon, and a blocked bed says why.

- **Live:** `GET /beds/events` is followed through `followEventStream` (`hooks/use-board.ts`). An event carries only `{ wardId }`; the board reads again (debounced 300 ms, at most 1 s behind a steady flow), and once each time the stream opens. A board filtered to one ward ignores other wards' events. Without a stream (403, 503 or a lost connection) it reads every 15 s and says so.
- **Actions per row:** "Mark being cleaned" (available) and "Mark ready" (cleaning) use `POST /beds/{bedId}/housekeeping` with the bed's `version` and an Idempotency-Key (`bed:update`). "Block" (available, with a reason from a list in a panel) and "Put back in use" (blocked) use the wards API (`ward:manage`; the API also wants `ward:read`). A move the status does not allow is disabled in the UI (`allowedActions`), the server's 409 is the authority: `conflict`, `invalid_transition`, `bed_not_available` and `bed_not_blocked` all read "Someone else changed this bed first", and the board is read again after every attempt.
- **The ward filter** (`WardFilter`, also on the census and in `BedPicker`) is left out without `ward:read`. It reads `GET /wards` (limit 100): a hospital whose wards fit gets a select; one with more (a `nextCursor`) gets a `ServerSearch` over ward code and name (`?q=`, 25 at a time), the chosen ward named under it with a button to clear it (#580).
- **Not here yet:** a ward map drawn as rooms and beds (the board is a list), counts per status, bed reservations. Occupied beds link nowhere yet.

**The admission workflow (#152, first slice):** `/admissions` lists admissions newest first (`GET /admissions`, filtered by status; the patient's name with the MRN masked) and `/admissions/new` admits a patient (`admission:create`). The form picks the patient (`PatientSearch`, or `?patientId=` and `?type=` in the address when another screen links to it), the admission type, the admitting doctor (`useDoctorOptions`; the caller's own profile when left empty) and **a free bed** from `BedPicker`, by ward and category. The desk never admits without a bed: with none free the form says so and the bed is a required field (the API would allow admitting without one). A bed taken first (409 `bed_not_available`) is let go and the beds are read again. The server opens the stay's inpatient encounter. A row's "Give or change bed" (`admission:transfer`) opens a panel with the same picker: `assign-bed` for an admission with no bed, `transfer` for one with a bed, sending the admission's `version`. The bed board links to the list (no second nav entry). Idempotency keys come from `hooks/use-admissions.ts`, one per request body. The mock keeps admissions in `mocks/handlers/admissions-flow.ts` and shows who sits in the beds it gave on the board.

- **Bed history (#153):** a row's "Bed history" (`admission:read`) opens a panel from `GET /admissions/{id}`: every bed oldest first, from and to, the calendar days each is charged for in the hospital's time zone (`stayDays`, a guide only), why the patient left and a note where the bed category differs from the stay before (a different day price, since the API keeps category and service as they were). The bed panel takes an optional reason (a list) and note (#574), shown in the history as "Moved here"; each stay shows the day price and days times price (`dayPriceMinor`, from the API; the amount is a guide, billing posts the real day charges from `bed.assigned`/`bed.released`).

- **Discharge (#577):** a row's "Discharge" (`admission:discharge`, admitted rows only) opens a panel with how the stay ends (`DischargeType`) and `POST /admissions/{id}/discharge` with the admission's `version`. 409 `unsigned_notes` keeps the panel open and says to sign or discard the drafts in the consultation; `encounter_not_open` is explained; `conflict`/`invalid_transition` close the panel and the list is read again. Not built (API has nothing): discharge clearance, summary, bill check.

- **Advice, attendant, deposit and consents (#575):** the admit form has optional fields for the doctor's advice, the attendant (name, relation from a list, phone), the deposit asked for and four consents (checkboxes). The deposit is typed in the hospital's currency and sent in minor units through `toMinor`; it is a record of the amount, nothing is taken or posted to billing. Sent only when filled; never changed after admission. Not shown on the list or history yet.
- **"Admit to hospital" links (#576):** `AdmitAction` is contributed to `patient.detail.actions`, `encounter.detail.actions` (open visits only) and a new slot `emergency.case.actions` (patient identified, not yet disposed; passes `admitType: 'emergency'`), for `admission:create`. It opens `/admissions/new?patientId=&type=`; the form fills the patient.

- **The visit it came from (#678):** `AdmitAction` on `encounter.detail.actions` adds `?encounterId=` to the link; the form sends it as `sourceEncounterId` (only for the patient the link was for) and the API keeps it on the admission (422 `unknown_encounter` unless it is a non-inpatient, non-cancelled visit of that patient). Not shown anywhere yet.

- **Bed tariff (#578):** `BedPicker` shows "{price} a day" under the category: bed category by name (`useBedCategories`, `ward:read`) -> its bed-day `serviceId` -> the service's `currentPrice` (`useServicePrices('bed')`, `service:read`). The board payload carries only `categoryName`, so the join is by name (unique per hospital). Any missing step leaves the price out, no error.

- **Census (#154):** `/census` (`admission:read`, linked from the bed board, no nav entry): the occupancy summary and the admitted patients (ward, bed, doctor). Counts come from one request, `GET /beds/counts` (#734, the same beds as the board lists; the capacity widget uses it too, one request instead of four); the rate leaves blocked beds out. The list is `GET /admissions?status=admitted` with the ward filter, paged. Both sit under the `bedKeys` so the bed events refresh them. **Not built, the API has nothing:** expected discharges (no expected-discharge date on an admission) and a filter by doctor (the doctor is a column).

## Decisions

- The board never keeps a patient in the query cache beyond the list itself; no cache entry is written by an action, which asks for the board again.
- Blocking uses the wards endpoints directly from this module's `api.ts`, not the `wards` module's internals; the reason list is repeated here (`BLOCK_REASONS`) and must follow the API's.
- The mock (`mocks/handlers/admissions.ts`) reads the beds from the wards mock (`mockBoardBeds`, `housekeepMockBed`), so one set of beds serves both screens, and every change of a bed there publishes on the mock stream. Only the sample hospital has `admissions` on.

- Admission details (#630): the "Admission details" row action opens `AdmissionDetailsPanel` with the advice, attendant (phone masked), deposit and consents recorded at admission; the list has a Deposit column. There is no separate detail route.

- **End-to-end (#155):** `e2e/admissions.spec.ts` admits a patient, moves them to another bed, reads the bed history and finds the bed in use on the board, at all three widths, with axe and a keyboard check of the admit form. The unit tests already cover the two hospitals (the clinic has no bed board). A selected bed in `BedPicker` uses `text-foreground` for its secondary lines: muted text on the accent background failed contrast.
